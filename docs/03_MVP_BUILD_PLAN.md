# 03 · MVP build plan и Lovable handoff

## Фактическое состояние

В main есть продуктовая документация и прототип маскотов коллеги. Локально есть незакоммиченная React + TypeScript + Vite заготовка; она не меняется и не публикуется этой задачей. Отдельного 04_UI_KIT.md нет. Прототип маскотов и статические ответы не подтверждают готовность функционального P0. Перенос в Lovable и провайдеры не считаются автоматически настроенными.

## Приоритеты

| Уровень | Объём |
| --- | --- |
| P0 | Пять коротких экранов onboarding; шесть маскотов, сохранение/смена; «Сегодня» с ручной отметкой симптомов, интенсивностью/влиянием и выбором позы |
| P0 | Отдельный экран настоящего двустороннего диалога: минимум последовательный голос STT → AI → TTS, исправляемая расшифровка, несколько реплик, текстовый fallback, три режима и безопасная ветка X |
| P0 | Проверка извлечённых наблюдений перед историей; создание/сохранение текстовых и голосовых опор, подходящая собственная опора на T и субъективная полезность |
| P0 | Ежедневный план: гибкие действия, простой блок привычек, отдельно вручную внесённые рекомендации с источником/датой/показателем; корректный процент |
| P0 | История, простая аналитика 7/14/30, настоящая генерация вопросов/сводки по выбранным данным, редактирование и копирование; профиль и четыре упрощённых раздела D, базовый контроль сохранения/удаления |
| P1 | Более подробные состояния маскотов; расширенное редактирование/удаление карточек опор; архив разговоров по согласию; расширенная аналитика; дополнительные персональные предложения; гибкое расписание привычек |
| P2 | Часы/кольца; импорт анализов/документов; кабинет специалиста и клиники; расширенная библиотека; длительная персонализация на больших данных |

P1-редактор опоры не отменяет P0-контроль удаления через «Мои данные». Простая аналитика P0 обязательна, расширенные графики — P1. Полный P0 сохраняется, даже если не помещается в три часа.

## Минимальный демонстрационный путь внутри P0

Наивысший приоритет: настоящий голосовой диалог, собственная опора и оба сценария. Минимум: O/T/M; две связанные голосовые реплики с текстом и озвучиванием → V; текстовое письмо A-S1 в хороший день → открытие в сложный → принятый P-A1; B с R-01, тремя гибкими действиями, 67%, подтверждённой историей и генерируемыми вопросами/сводкой.

Можно сократить глубину интерфейса: один язык, одно устройство, push-to-talk вместо streaming, простая схема подбора опоры вместо векторного поиска, списки вместо сложных графиков, копирование вместо PDF. Минимальный показ не требует записи голосовой опоры, полного редактора привычек и заполнения всех добровольных полей; эти требования не удаляются из полной спецификации. Пропущенные P0 фиксируются как незакрытые, без объявления полной готовности.

Нельзя сокращать реальный диалог до статического ответа, подтверждение данных, отделение рекомендаций, формулу прогресса или один из сценариев. Если голос недоступен, видимый текстовый резерв/подписанное видео помогает провести показ, но не закрывает голосовой P0.

## Зависимости и порядок

1. Проверить реальную цепочку микрофон → STT → AI с контекстом → TTS на устройстве показа, до полировки.
2. Общие профиль/дата/навигация → O/T/M → подтверждённая запись → маскот.
3. C → принятый текст → V → история; опора и шаг сохраняются отдельными действиями.
4. S + подтверждённая отметка + предпочтение/полезность → предложение опоры на T.
5. Гибкие действия/экземпляры привычек → статусы → одна формула для T/P; R-01 отдельно.
6. Подтверждённая история → аналитика → выбранные ID → AI-вопросы/сводка → проверка/копирование.
7. Изоляция профилей, сохранение/удаление и ошибки проверяются до презентации.

## Три часа

| Интервал | Работа | Контрольная точка |
| --- | --- | --- |
| 0–15 мин | Загрузить требования, разделить задачи, проверить доступы и минимальный настоящий голос | Работают микрофон, распознавание, ответ и озвучивание; выбран способ сохранения |
| 15–105 мин | Сначала сквозной A: общие O/T/M, C/V, письмо/подбор опоры, принятый шаг; затем профиль и базовый план | A можно пройти без статической подмены, данные сохраняются |
| 105–135 мин | Ветка B: рекомендация, прогресс, синтетическая история, простая аналитика и генерация сводки/вопросов | B согласован с числами 02 |
| 135–165 мин | Исправления, контроль данных/ошибок/X, репетиция A/B | Показ 3–4 минуты, список незакрытого P0 явен |
| 165–180 мин | Резерв, запись проверенного показа | Есть честно маркированный резерв |

Итого 180 минут. Роли: голос/AI и безопасный вызов; интерфейс/навигация; данные/опоры/план/сводка; проверка/показ. Совмещение зависит от состава команды. Если 90-минутный блок задерживается, сокращать декоративную глубину и P1, не скрывать отсутствие ключевых функций.

## Lovable handoff

Контекст передавать явно: README → 00 → **05 целиком** → 01 → 02 → этот план. Затем дизайнерские материалы/согласованный UI-kit. Не предполагать, что ссылка на WWAI импортирует файлы или синхронизирует существующий код. Проверить поддерживаемый путь текущего аккаунта/проекта; при необходимости передать документы вручную. Согласовать целевой репозиторий/ветку, не перезаписывать WWAI экспериментальным экспортом.

Первый запрос в Lovable: общий каркас экранов и минимальный путь, затем отдельная проверяемая задача на настоящий голос. Следующие задачи — подтверждение наблюдений, письмо/подбор опоры и план, затем B. Использовать одинаковые сущности из 05, а не два независимых демо.

Подготовить DEMO-A/DEMO-B, A-S1, R-01, пять B-записей, три гибких действия, фиксированные даты и ожидаемые значения 02. A-S1 в основном показе создаётся заново; резервный seed маркируется. Прогресс не подставляется готовым числом: считается из статусов. Не загружать реальные истории участников.

Для голоса могут понадобиться разрешение микрофона и безопасный контекст браузера, STT, AI с контекстом сессии, TTS, разрешённое пользовательским действием воспроизведение. Проверить поддержку русского языка, браузер/аудиоформат, задержку, лимиты и ошибки. Наличие текстовой AI-функции не доказывает наличие STT/TTS.

Вариант для оценки — доступные встроенные AI-возможности Lovable; альтернатива — внешние API через один защищённый серверный вызов. Провайдеры не утверждены. Ключи при их необходимости хранятся в серверных секретах/управляемом backend, не в frontend, VITE-переменных, Git и логах. Для трёх часов не нужны микросервисы, vector DB, клиники или отдельная промышленная инфраструктура. Синтетическое сохранение должно переживать повторное открытие и изолировать профили; реальные чувствительные данные требуют отдельной проверки доступа/хранения.

Официальные материалы, проверенные 15.11.2026: [GitHub sync](https://docs.lovable.dev/integrations/github), [AI features](https://docs.lovable.dev/features/ai). Их наличие не подтверждает настройки нашего проекта, доступы или оплаченные лимиты. Не подключать и не публиковать ничего в рамках текущей документационной задачи.

## Риски голосового режима

| Риск | Действие |
| --- | --- |
| Нет микрофона/отказ | Сразу текст без потери принятого; показать незакрытый голосовой критерий |
| STT ошибается | Редактирование перед отправкой, наблюдения требуют проверки |
| AI недоступен/теряет контекст | Повтор принятой реплики без дубля; проверить две связанные реплики до показа |
| TTS/автовоспроизведение заблокировано | Явная кнопка слушать, текст остаётся, повтор озвучивания |
| Долгая задержка/квоты | Проверка в первые 15 минут; короткие ответы и видимые статусы, без ложной готовности |
| Утечка/смешение данных | Только синтетические профили, изоляция, секреты на сервере, без чувствительных логов |
| Сервисы не восстановлены | Подписанный резерв, статусы функций объявляются честно; полный P0 не считается готовым |

## Ручная приёмка до презентации

- [ ] O: назад/вперёд, пропуск добровольного, отсутствие диагноза; шесть персонажей и смена сохраняются.
- [ ] M: интенсивность/влияние, отмена, подтверждение, нет дубля; несколько симптомов → выбор позы без перекраски.
- [ ] C: две реальные голосовые реплики, связный AI, текст и слышимый ответ; остановка, отказ микрофона, ошибки STT/AI/TTS.
- [ ] V: исправление текста/наблюдения, исключение, неизвестная выраженность, отсутствие автоматической записи фактов.
- [ ] S: письмо в хороший день → тот же текст в сложный; отказ/другая опора, «Подошло», отдельное принятие шага.
- [ ] P: 0/3 → 33% → 67%; skipped/deferred исключены; нет задач → без процента; рекомендации не меняются и не считаются.
- [ ] H: числа 7/14/30 из 02, пропуски без догадок, нет причинных выводов; вопросы/сводка опираются на выбранные ID и обновляются при снятии выбора.
- [ ] U/D: добровольные поля, контроль сохранения/удаления, изоляция A/B; повторное открытие плана/опор.
- [ ] X: явная непосредственная опасность прекращает обычные задания, направляет к человеческой помощи, не обещает автовызов.
- [ ] 390/1440 px, клавиатура, фокус/контраст, казахские буквы; нет потери основных действий.
- [ ] Проверены ключи/лимиты/звук на устройстве показа; синтетика и деморежим подписаны, реальная функция отличима от резерва.
- [ ] Репетиция A/B 3–4 минуты; все незакрытые P0 перечислены, снимок/видео не выдаётся за текущую генерацию.
