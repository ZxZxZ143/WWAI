# 05 · Функциональная спецификация Қолдау

[Контекст](00_PRODUCT_CONTEXT.md) · [Истории](01_USER_STORIES.md) · [Демо и данные](02_DEMO_SCENARIOS.md) · [План](03_MVP_BUILD_PLAN.md)

Версия 15.11.2026. Главный источник поведения для дизайнера и разработки. Требования целевые; приоритеты и минимальный путь — в 03. Правила подтверждения и безопасности действуют во всех вариантах.

## Карта экранов и переходов

| ID | Экран | Переходы |
| --- | --- | --- |
| O1–O5 | Onboarding | Знакомство → маскот → темы → поддержка → специалист → T |
| T | Сегодня | Ручная отметка M, разговор C, опора S, план P |
| M | Отметить самочувствие | Проверка → сохранить → T/H; отмена без записи |
| C | Разговор с Қолдау | Голос/текст → несколько реплик → V; закончить без сохранения → T |
| V | Проверь наблюдения | Исправить/подтвердить → H; отдельно опора S или шаг P; возврат C |
| S | Мои опоры | Создать/открыть, обратная связь; принять предложенный шаг → P |
| P | Мой план | Шаги, привычки, рекомендации; добавление рекомендации; обновление T |
| H | История и консультации | Лента → период/аналитика → записи/вопросы → сводка |
| U | Профиль | Маскот, поддержка, голос/текст, специалист; Мои данные D |
| D | Мои данные | Добровольные поля, сохранение/удаление → U |
| X | Срочная человеческая помощь | Отдельная безопасная ветка из C без обязательных задач |

Постоянная навигация: «Сегодня», «Мои опоры», «Мой план», «История и консультации», «Профиль». M, создание опоры/рекомендации и выбор персонажа допустимы как панели. Оба профиля используют одни экраны; специалист не является условием доступа.

## Onboarding O1–O5

Назад/вперёд сохраняют черновик. O1 объясняет поддержку, опоры и добровольность сведений; «Начать». O2 — шесть radio-карточек и подтверждение; выбор сохраняется и меняется позже в U.

O3 — множественный выбор: «Сон и усталость», «Приливы и ощущение жара», «Перепады настроения», «Тревожность и раздражительность», «Трудности с концентрацией», «Другие симптомы» с необязательным уточнением. Можно пропустить. Это темы интереса, не подтверждённые симптомы сегодняшнего дня; историю они не заполняют.

O4: «Бережно выслушивать» → «Выговориться»; «Помогать разобраться в переживаниях» → «Разобраться»; «Предлагать небольшие посильные действия» → «Выбрать небольшой шаг». Можно пропустить; все три режима доступны всегда.

O5: «Да, я уже наблюдаюсь и хочу сохранять рекомендации» / «Пока нет, хочу лучше разобраться в происходящем». Пропуск даёт «Не указано». Диагноз и большая анкета не нужны. «Перейти в Қолдау» открывает T. Остальные сведения собираются постепенно.

## Сегодня T и ручная отметка M

T: выбранный маскот в полный рост, «Отметить самочувствие», крупное «Рассказать, как я», одна актуальная опора и компактный план с прогрессом/переходом P. Без опор — обычная поддерживающая карточка. Не перегружать главную графиками.

M: дата/время (сейчас по умолчанию), самочувствие «Хорошо / Непросто / Не хочу оценивать», несколько симптомов, необязательная интенсивность каждого («Слабая / Умеренная / Сильная»), влияние («Не мешает / Немного мешает / Сильно мешает / Не указано»), свободный контекст. Неназванная интенсивность — «Не указано». Хороший день допустим без симптомов. Полностью пустую запись не сохранять: попросить состояние, симптом или текст.

Предпросмотр → «Подтвердить и сохранить» создаёт одну запись с источником «Ручная отметка» и обновляет T/H. Повторное нажатие не дублирует запись; отмена ничего не сохраняет. Хороший день предлагает создать опору, сложный — открыть подходящую, начать разговор или отказаться.

## Логика маскотов

Персонажи: cat — кошка, rabbit — зайка, bear — медведица, fox — лисица, capybara — капибара, borzoi — борзая. Единые позы: base — обычное; energized — бодрость; reflective — задумчивость; tired — усталость; hot_flash — прилив; anxious — тревога; resting — отдых.

Поза и тема независимы. Смена животного не сбрасывает рассказ, данные, план или позу. Подтверждённые усталость/плохой сон позволяют предложить tired, жар — hot_flash, тревога — anxious. При нескольких симптомах женщина выбирает главное состояние; до выбора остаётся предыдущая поза. Хороший день позволяет предложить energized. reflective/resting не определяются скрыто по голосу. Без данных — base; ручной выбор доступен всегда.

Нет диагноза, батарейки здоровья, оценки нормы или зависимости персонажа от посещений/задач. Недостающая поза заменяется базовым образом того же животного и текстовым описанием. Требование полного роста T сохраняется, даже если временный фрагмент только портретный.

## AI-разговор C

Экран содержит текущий формат и переключение всех трёх режимов, микрофон, текстовое поле, текст ответов, озвучивание/остановку, «Закончить». Разрешение микрофона запрашивается после явного действия. До начала объяснить передачу аудио на распознавание и текста для ответа, раскрыть фактические сервисы и хранение.

Последовательность P0: говорить → остановить → распознавание → исправляемая расшифровка → принять/отправить → настоящий AI-ответ текстом → услышать ответ → следующая реплика. Минимум две связанные реплики; streaming необязателен. AI учитывает принятые реплики сессии. Автоозвучивание возможно по предпочтению после первого действия. Запись не идёт одновременно с воспроизведением. Можно остановить, сменить режим, перейти к тексту и закончить.

«Выговориться» — внимательный ответ без заданий; «Разобраться» — необязательные вопросы/формулировки; «Выбрать небольшой шаг» — несколько посильных вариантов без принятия по умолчанию. Разрешённый контекст персонализации: подтверждённые записи, предпочтения, доступные опоры и оценки полезности. Нет диагноза, изменения лечения и автоматического объяснения переживаний гормонами; AI не заменяет специалиста по психическому здоровью.

Сбой STT оставляет текстовый ввод; сбой AI — принятую реплику и повтор без дубля; сбой TTS — настоящий текстовый ответ и повтор озвучивания. Выход останавливает захват/воспроизведение; поздний ответ не сохраняет ничего сам. Fallback использует настоящий AI. Неработающий STT/TTS означает незакрытый голосовой P0.

## Переход к подтверждённым наблюдениям V

Поддержка происходит во время C до структурирования истории. На завершении предложить V либо «Закончить без сохранения». Различать исходную речь, принятую расшифровку, предложения AI, подтверждённые наблюдения, сохранённую опору и принятый шаг.

Из принятого текста предлагаются симптомы, явно названная выраженность, контекст, влияние, потребность в поддержке, полезные мысли/действия. У наблюдения видны цитата-основание, редактирование и включение/исключение. Неназванное не вычисляется. Правка текста требует повторной проверки связанных предложений. Можно исключить всё.

В историю попадает только подтверждённое как самоотчёт с датой/источником «Разговор». Хранение текста — отдельный выбор; весь разговор автоматически не сохраняется. Опора и шаг сохраняются отдельными действиями; одно не требует другого. Ошибка оставляет черновик, успех только после записи данных.

## Мои опоры S

Типы: письмо будущей себе; голосовое послание; мысль; субъективно помогающее действие; подготовленная просьба близкому; формулировка из AI-разговора. Поля: ID, тип, название, текст/аудио, дата, авторство/источник, необязательные темы, связи с записями и оценки полезности с датами. «От тебя для себя» отличается от «Из разговора · сохранено тобой».

Создать → написать/записать → просмотреть/прослушать → сохранить или отменить. Аудиопослание сохраняется только отдельным явным действием. Полная P0-функция предусматривает текст и голос, минимальный показ A использует письмо. Расширенное редактирование/удаление карточки — P1; контроль удаления сохранённого содержимого через D обязателен в P0.

Хороший день: «Хочешь оставить несколько слов себе на день, когда будет труднее?» Сложный: «Ты оставила себе небольшое послание. Хочешь открыть его?» Можно выбрать другую опору/формат или отказаться. Нет автоматического воспроизведения личного аудио. После открытия необязательные «Подошло / Не сейчас / Не подошло»; «Не сейчас» не отрицательная оценка.

Минимальный подбор: только собственные опоры, совпадение подтверждённой темы, формат, прежняя полезность; при равенстве — более новая. Учитывать доступность текста/аудио и разрешение персонализации. Без совпадения предложить ручной выбор. Не гарантировать улучшения. Действие становится шагом P только после принятия.

## Мой план P и процент

Три самостоятельных раздела:

1. **Мои шаги на сегодня:** конкретное название, дата, источник (сама/опора/разговор), статус и изменение. Вручную или после принятия предложения.
2. **Повторяющиеся привычки:** собственный ритуал и простой ритм; на сегодня отдельный экземпляр после включения женщиной. Гибкое расписание — P1.
3. **Рекомендации специалиста:** исходная формулировка, дата, источник, связанный показатель, если указан; «Внесено вами». При правке сохраняется исходная формулировка; AI не переписывает назначения.

Статусы гибкого действия: pending — ожидает, completed — выполнено, skipped — пропущено, deferred — перенесено на выбранную другую дату. Можно выполнить, отложить, пропустить, изменить и вернуть completed в pending. Привычка учитывается один раз за день по экземпляру. Рекомендации и медицинские назначения не входят в процент и не имеют игровой оценки соблюдения.

**Формула:** `completed / (completed + pending) × 100` для выбранных гибких действий текущей даты. Округление до целого, 0,5 вверх. skipped и перенесённые deferred исключены. При нулевом знаменателе процент/кольцо скрыты: «На сегодня нет выбранных действий».

2 выполнено + 1 ожидает = 67%; пропуск оставшегося → 100%; все пропущены → без процента. Подпись «Личные действия на сегодня», нейтральный вид при низком проценте. Это не здоровье, эмоциональная норма или эффективность лечения.

T показывает тот же расчёт и 1–3 пункта, P — полный список. День — локальная дата женщины; демо Asia/Almaty. Новый день не создаёт долг из вчерашнего. При тяжёлом состоянии можно предложить упростить необязательное, при хорошем — рефлексию/опору. Любое изменение гибких действий требует подтверждения; рекомендации не затрагиваются.

## История, аналитика и консультации H

Лента: ручные отметки и подтверждённые наблюдения разговоров, дата/источник, интенсивность, влияние, контекст, выбранная поддержка и полезность. Деталь показывает происхождение.

Периоды 7/14/30 дней включают выбранную локальную дату и предыдущие 6/13/29 дней. P0 — простая описательная аналитика; P1 — расширенные графики/фильтры. Частота — число дней с симптомом, несколько записей не увеличивают число дней. Подпись «в N из K дней с записями» и число дней без данных. Пропуск не равен отсутствию симптома. Интенсивность — известные исходные категории/временной ряд без выдуманных средних. Сочетание — совместная отметка в одной записи, не причина. Полезность субъективная, не эффективность лечения.

Выбрать период/записи → настоящий AI предлагает сводку и вопросы → проверить основания → изменить/исключить → предпросмотр → отдельно копировать. Каждое обобщение и вопрос связаны с ID выбранных записей. Снятие выбора инвалидирует зависимый текст и предлагает обновление. Без записей не генерировать закономерности. В сводке: частота, изменения, влияние, что пробовала и хочет обсудить — только при наличии оснований. «По вашим записям», «вы отмечали»; без диагноза и неподтверждённых причин.

Вопросы редактируются/выбираются, например: «Какие причины ночных пробуждений стоит обсудить?» Сводка доступна без специалиста. Копирование/будущая отправка только отдельным действием; MVP не отправляет автоматически, не записывает на приём, не требует сложного экспорта.

## Профиль U и Мои данные D

U: маскот, режим поддержки, голос/текст и озвучивание, статус специалиста. Черновики не сбрасываются.

| Раздел D | Состав и граница |
| --- | --- |
| Основная информация | Добровольные возрастной диапазон, собственное понимание этапа («не знаю»), приоритеты |
| Менструальная история | Необязательные цикл/последняя менструация; этап автоматически не вычисляется |
| Состояния и заболевания | Добровольный текст «Со слов пользовательницы» |
| Лекарства и терапия | Добровольные рекомендации с датой/источником; без назначения/коррекции |
| Репродуктивная история | Необязательное расширение вне минимального пути |
| Анализы и документы | P2, без реальных медицинских документов в MVP |

Первые четыре — упрощённые формы MVP, не обязательная анкета. Различать захват/передачу аудио, сохранение текста/послания и разрешение персонализации. Разговорное аудио по умолчанию временное: удаляется после обработки/отмены. Голос-опора сохраняется отдельно. Архив прошлых разговоров — P1.

D показывает категории сохранённого и удаление выбранного/всего содержимого после понятного подтверждения. Удаление убирает связанные ссылки персонализации, инвалидирует сводки, пересчитывает аналитику. Отказ от персонализации не блокирует поддержку. Для прототипа только синтетические данные; до реальных нужны фактические сервисы, сроки хранения, изоляция доступа и проверяемое удаление. Ключи и чувствительные данные не попадают в Git, клиентский bundle и публичные логи.

## Пустые, ошибочные и безопасные состояния

| Состояние | Поведение |
| --- | --- |
| Нет истории/опор/действий | Приглашение начать, обычная карточка, без выдуманных данных/процента |
| Нет микрофона/отказ | Объяснение, тот же диалог через текст, без потери принятых реплик |
| Запись/STT/AI/TTS | Различимые статусы, остановка, повтор; успех только по результату |
| Ошибка сети/сохранения | Черновик остаётся, повтор без дублей; нет ложного успеха |
| Нет подходящей опоры | Ручной выбор/другой формат без ложной персонализации |
| Ошибка сводки | Записи доступны, повтор; статический текст не выдаётся за генерацию |
| Непосредственная опасность X | Прекратить обычные задания; направить к срочной человеческой помощи |

X применяется при явной непосредственной угрозе жизни/самоповреждении или срочной опасности, не при каждой тревоге. Текст: «Сейчас важнее получить помощь человека. Обратись в местную экстренную службу или к человеку рядом, который может помочь тебе связаться с ней». Не обещать наблюдение, автоматический вызов или уведомление близких. Конкретные контакты только после проверки для страны, номера не выдумывать. Опоры/план не заменяют помощь. Ветка проверяется вручную; клиническая валидация не заявляется.

## Общая логика и изменения для дизайнера

A: O → T → M → S, другой демонстрационный день T → M → C → V → T → S → P. B: U/P → T → M → P → H. Общие компоненты и сущности; данные в 02, критерии в 01.

Найден [прототип коллеги](../prototypes/peri-mascot-animations.html); отдельного 04_UI_KIT.md нет. Локальный React UI-preview — ранняя заготовка, не функциональное приложение. Код и ассеты не меняются. Дизайнеру:

- заменить Peri названием Қолдау в пользовательском интерфейсе;
- сохранить шесть животных, согласовать base и семь единых ID; полный рост T, компактные версии для форм;
- убрать батарейки/числовую энергию, постоянное дрожание/прыжки; поддержать reduced motion, чистые фрагменты и контраст;
- добавить пять экранов onboarding, полноценный разговор с текстом/озвучиванием и отдельное V;
- разделить «Мои опоры», три части плана и нейтральный процент;
- предусмотреть интенсивность/влияние, основания аналитики/вопросов, U/D, X и ошибки.

Доступность: текст ≥ 4,5:1; значимые границы/иконки ≥ 3:1; видимый фокус, подписанные поля, клавиатурный выбор и возврат фокуса из диалога. Русские/казахские буквы, 390/1440 px, увеличение масштаба без потери действий. Визуальный пример не заменяет бизнес-правила.
